## Descripción
Pruebas de aceptación de `POST /api/ventas` con Supertest y una base en memoria (`abrir(':memory:')`), en un archivo **aparte** de las pruebas de quien implementa (`test/ventas-aceptacion.test.js`), como se hizo con HU-05.2 en el Sprint 2. Cubren los CA de HU-01 que se pueden comprobar en la API, a partir del contrato de `docs/arquitectura/api-ventas.md`. Si una prueba falla, se registra un issue `bug` en vez de corregir el código.

## Lo que ya existe
- Base en memoria y datos de prueba en `test/lotes.test.js` y `test/stock.test.js`.
- `POST /api/ventas` ({{HU-01.2}}) con el `409` de stock insuficiente ({{HU-01.3}}).

## Criterios de aceptación
- [ ] **CA1:** una venta válida responde `201`, guarda fecha y hora (`AAAA-MM-DD HH:MM:SS`), líneas y monto, y `GET /api/stock` baja en la cantidad vendida.
- [ ] **CA2:** 4 u. en stock, venta de 5 → `409` con `disponible: 4`; no se crea ninguna venta.
- [ ] **CA3:** 10 u. a S/ 0.50 + 4 u. a S/ 1.20 → `monto_total_centimos: 980`.
- [ ] **Transacción:** una venta de dos productos con uno sin stock no guarda ninguna línea.
- [ ] **Precio del servidor:** si el cuerpo trae un precio inventado, el monto usa el precio guardado del producto.
- [ ] `npm test` pasa; los defectos encontrados quedan como issues `bug`.

## Dependencias
- {{HU-01.3}} Rechazo por stock insuficiente en la API
